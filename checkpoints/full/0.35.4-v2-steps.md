## How to run each step

Every step has the same four phases. Do not start the next step until the user reports the in-game result.

1. **Change the code** listed in the step. Read KNOWLEDGEBASE.md entries for the touched area first.
2. **Build.** Papyrus: VS Code task `compile: pyro` (must end with 0 failed). DLL: `CMake: Build SKSE (Release)`,
   never Debug (a Debug DLL crashes on load, KNOWLEDGEBASE "Debug-built SkyrimNet_SexLab.dll"). Confirm the copy
   landed in `SKSE/Plugins/SkyrimNet_SexLab.dll` (timestamp, or `grep -c` for a new log string).
3. **Print the in-game verification instructions** for the step, verbatim from its "In-game verification" list,
   plus the log lines to look for.
4. **Stop and wait.** The user runs the test in game and reports back. On a failure, read
   `SkyrimNet_SexLab.log` / `Papyrus.0.log`, fix inside the same step, rebuild, and re-print the instructions.
   On pass, add a CHANGELOG.md "Unreleased" bullet for the step, and commit only if the user asks.

Line numbers drift with every step. Locate code by function name.

## Step 2 — Scene state correctness (implemented)

**Review IDs:** H2, H3, M1, M2. **Build:** `compile: pyro` only.

### What changed

| ID | Where | Change |
|----|-------|--------|
| H2 | `Scene.psc` `SetActor` | Reads the actor's old `storage_obj_key` first. If it is one of this scene's `position_objs` (same or moved slot), `total_orgasm` / `orgasm_narrated` keep the actor's StorageUtil values; otherwise 0 as before. Read per actor, not from the old obj, so a two-actor slot swap can't read an already-overwritten obj. |
| H2 | `Scene.psc` new field `storage_orgasm_narrated_key` | `skyrimnet_sexlab_scene_orgasm_narrated`, under `storage_prefix` so load wipes it with the totals (L4 still deferred). Written by `SetActor` and `MarkOrgasmNarrated`, unset in `Release`. |
| H3 | `Actions.psc` `TM_SetClothed` | Scene looked up by `a`. In a scene: `sl.ApplyDressedToActor` + `sl.TM_ApplyClothed`. `Outfit_Dress` / `Outfit_Undress` only when there is no scene. |
| H3 | `Scene.psc` `ApplyDressedToActor` | Guard: returns when `thread` or the actor is None. |
| M1 | `Scene.psc` new `RefreshVictimRoles()` | `ReconcileVictimFactions()`, then rewrite `victim` / `assailant` on every position (same rule as `SetActor`), then `SetNames()`. Does not recompute `initiator`. |
| M1 | `Scene.psc` new `TM_ApplyVictim(a, isVictim)` | `thread.SetVictim`, `RefreshVictimRoles()`, and `NarrateVictimToggle` when the value changed (same narration as the Description Editor V toggle). `Actions.TM_SetVictim` now calls it instead of the thread. |
| M1 | `Scene.psc` `WebUI_ApplyLivePositions` | Calls `RefreshVictimRoles()` after the SetVictim loop when any victim changed, before narrating. |
| M2 | `Scene.psc` `Release` | Clears `user_anim_defaults` and sets `played_registries_count = 0`. |

Known edge, not fixed: an actor who leaves a scene mid-way keeps a `storage_obj_key` into that pool scene. If they
rejoin the same reused scene slot before a load, they inherit their old orgasm count.

**In-game verification**
1. Start a scene where one actor orgasms twice (SexLab orgasm hotkey or SLSO). Toggle O on that actor in the
   Description Editor, then trigger a third orgasm. Expect: narration says "again"; the end afterglow says
   "orgasmed 3 times". Log: `total_orgasm` 3 in the thread JSON dump.
2. Change animation (SL Tools list) after two orgasms. Expect: the count still carries (third is "again").
3. Mid-scene, TargetMenu → clothed off for one actor, then end the scene. Expect: SexLab re-dresses the actor.
   Repeat with clothed on: the actor dresses mid-scene.
4. Mid-scene, toggle V on one actor in the Description Editor. Ask an onlooker NPC what is happening.
   Expect: assault phrasing; thread JSON shows `victim:1` on that actor and `assailant:1` on the other.
   Repeat from the TargetMenu victim toggle: same result, plus a "starts sexually assaulting" narration.
5. End the scene and start a new one with different actors on the same animation. Expect: the new cast gets the
   animation's defaults, not the previous cast's O / modifiers.

Log lines: `SetPosition ... end index:` traces keep firing on O / animation changes without the count resetting;
`GetIsOrgasming ... total_orgasms:3`; no `Outfit_Dress ... has no stripped items` for a scene actor.
