## Layout

```
| ControlPanel (10% top/left) | Main panel (10% top/bottom/right) |
| TargetMenu (same width)     |                                     |
```

- **ControlPanel** (`#control-panel`): row 1 **mode** pulldown (`#control-mode-pulldown`, same widget as views/target; built-in `SkyrimNet SexLab` plus `webui/ControlPanel/*.json`); then **views** label (75% of `--text-base`) above an indented `main_panel` pulldown (from the **active mode** `MainPanels/`, with JS builtin fallback in SexLab mode); OStimNet-gated **framework** pulldown (`#framework-row`, `sexlab`/`ostim`, no label, hidden unless OStimNet or the mode sets `hideFramework`); then **target** label (same 75% size) above an indented **actor focus** pulldown (`#control-actor-pulldown`, nearby actors plus mode **sentinels**). Main-panel list includes **None** (clears the right main-panel host). Pulldowns stay **vertically aligned with the trigger**; only the left offset uses `--space-md` from the ControlPanel box (same gap as TargetPanel → Parameter Panel). Menus stack above TargetPanel and the main panel and use an opaque background.
- **Actor focus pulldown:** nearby actors (player pinned first), sorted sexlab → eligible → ineligible, then distance. Labels: name cropped to 10 chars; `(sexlab)` selectable; no suffix = eligible; `(reason)` greyed (`child`/`cmbt`/`ostim`/`dead`/`load`, ≤5 chars). Selection sets `Target_Current` and switches the selected **SceneInfo** to that actor’s thread if any, else the Scene Creator (`new`) SceneInfo. Default: player animating → first non-player in the player's scene from position 0 (player if solo); otherwise crosshair if present, else nearest selectable non-player, else player.
- **Paused while open by default:** `Focus(view, true)` on Show/Hide (JS `setGamePaused(true)`). Only the Description Editor **play/pause** button changes it: JS `onGamePauseSet('1'|'0')` → C++ `Unfocus` then `Focus(view, paused)` (a repeat Focus alone does not change the pause state). Log tailing is file I/O and still works. AnimDB rebuild that needs `RegisterForSingleUpdate` waits until the overlay closes.
- **TargetMenu:** stacked under ControlPanel in the left column (no actor name header — focus is the ControlPanel pulldown).
- **Main panel host:** one visible panel at a time, selected by the pulldown (builtin **Scene** / Log / Settings, plus mode panels). **Close** (`#main-panel-close`, `mainPanelClose()`): one button in the same top-right spot of every main panel (Scene, Settings, Log, foreign `papyrus` / `data_table` / `actor_detail`); returns the view to **None** with the overlay still open (C++ `SwitchMainPanel('')` still runs a foreign panel's `closeFunction`). Each panel's first row has right padding so nothing sits under it. Scene Menu (`#scene-creator-panel`) fills the host; **Animations list is a fixed 50%** of the panel (scroll inside `#sc-anims-list`). Positions + Filter share the remaining height and scroll internally. Filter’s available-tags region (`#sc-available-tags`) is **2×** the selected tags+suppress rows; those chip lists scroll internally.
- **Scene view (`scene_panel`):** one MainPanels entry (**Scene**) that shows the **Description Editor** when the ControlPanel target is in a SexLab scene (SexLabAnimatingFaction) and the **Scene Creator** otherwise. C++ resolves it (`ActionCatalog` `OpenMainPanelEntry` → JS `revealMainPanel('scene_panel', '<scene_creator_panel|description_editor_panel>')`, kept in `g_scenePanelResolved` / JS `SCENE_PANEL_RESOLVED`); `IsMainPanelOpen("description_editor_panel")` is true while the Scene view shows the DE. Old builtin keys `scene_creator_panel` / `description_editor_panel` are aliases (catalog entries collapse into one **Scene**, `SwitchMainPanel` and JS `showPanel` map them). Re-selecting the Scene view re-resolves, so a ControlPanel actor change flips DE ↔ Scene Creator. Scene start/end with the overlay open: `Scene.AnimationStart` / `AnimationEnd` call `WebUI_RerouteForFocus` → native `WebUI_RerouteScenePanel(inScene)` when the target is in that thread (told explicitly — the faction may not have changed yet inside those hooks). Scene Creator always binds the `new` draft.
- **Sticky Scene view (`show_scene_panel`):** opening the Scene view sets a C++ flag (`ActionCatalog::IsShowScenePanel`); while set, the Scene view opens with the WebUI (hotkey open, ControlPanel actor change → `WebUI_MaybeRestoreScenePanel`). Only the main-panel **Close** on the Scene view clears it (Scene Creator: `onSceneCreatorResult` `_action:"close"`, which also releases a Papyrus-origin creator; Description Editor: `onScenePanelClose`). Escape and Cancel close the WebUI and leave the flag set. With the flag off the hotkey opens no scene panel, even mid-scene.
- Sex Menu / YesNo remain overlay panels outside the main_panel pulldown.

### SceneInfo (shared scene draft)

JS `SceneInfo` map: one instance per active SexLab scene (`scene:<sid>`) plus one `'new'` Scene Creator draft. Seeded from Papyrus `BuildAllSceneInfosJson` on overlay Show (`SceneInfos_Seed`). Actor focus selects the thread that contains that actor, or `'new'`. Switching actors does not wipe `'new'`.

Panels copy the selected SceneInfo into a local draft on open. **Start / Done / Update / Stop / silent / explain** write the draft into SceneInfo. **Cancel** (and leaving a panel without confirming) does not. Overlay **Cancel** (Description Editor Cancel, TargetMenu Cancel → `onCancel`) hides **without** committing (`discardSceneInfos`): dirty SceneInfos and a pending actor reorder are dropped, and every live scene is sent `{_restore_snapshot:1}` so it goes back to its state from when the overlay opened (see **Cancel snapshot**). Every other hide — hotkey, **Escape**, Save, Scene Menu Start, TargetMenu action Start — commits (`flushSceneInfos`: a pending Description Editor animation pick, then dirty SceneInfos → `WebUI_OnSceneInfoCommit`) then Unfocus so `StartThread` can run. Both end with `clearSceneInfos()`.

**Cancel snapshot:** overlay Show → `Menu.WebUI_SeedSceneInfos` → `Scene_Manager.WebUI_TakeCancelSnapshots` → each active `Scene.WebUI_TakeCancelSnapshot` (plain script arrays: animation registries + forced flag, playing registry, stage, style, `seeded_registry`, and per actor `no_orgasm` / `deny_orgasm` / `dressed` / speaking CSV / the three `*_locked` flags / the in-scene undressed StorageUtil flag). `ApplyWebUICommit` `_restore_snapshot` → `WebUI_RestoreCancelSnapshot`: rebuilds the animation list, plays the snapshot's animation without reseeding or narrating, restores style silently, writes the actor values back (+ `DisableOrgasm`), re-dresses anyone undressed since, `GoToStage` to the snapshot stage. A no-op unless `cancel_dirty` (set by `WebUI_SwitchToRegistry`, a WebUI stage step, a WebUI style change). Stage text already autosaved to disk is not rolled back.

### Scene Menu + Description Editor connection

- Focus actor owns the selected SceneInfo (or `"new"` creator state). The Description Editor has **no scene pulldown**: it binds the ControlPanel target's live scene (`deBindTargetScene` → `deTargetSceneKey`; `DE.scenePick` is that `scene:<sid>`, or `none` while waiting for the seed / when the target is in no scene — header `Description (target is not in a scene)`). There is no None / Any / ended mode (Papyrus no longer keeps `last_ended_obj`). A push for another scene (`configureDescriptionEditor`) never re-targets the editor: `selectedSceneInfoKey` only follows a scene that contains the target. When the focused animation is playing in the bound scene, its current stage row gets a lighter background (`de-stage-active`).
- Opening Scene Menu / Description Editor binds the panel to the selected SceneInfo (`mainPanelDidOpen`). Do not re-fetch Papyrus snapshots on actor change (that wiped drafts).
- Description Editor lock: whenever the panel opens, `revealMainPanel` resets `DE.scenePick` to `none`, the bottom tab to **stage descriptions** and any pending pick, and calls `deSetLocked(true)`, showing `#de-lock-overlay` ("loading..." text, 10% down / 20% in, blocks input). `deBindTargetScene` releases it only once scene data exists (`sceneInfosSeeded`, set by `seedSceneInfos`). `concealMainPanel` / switching away unlock, and a timer (`DE_LOCK_TIMEOUT_MS`) binds as the fallback.
- **Description Editor bottom tabs** (`#de-tab-bar`, panel class `de-tab-stages` / `de-tab-filter`; one shown at a time, **stage descriptions** default): **stage descriptions** = the per-stage table. **animation filter** (`.de-animfilter-section`): a top row (`.de-animfilter-top`) with the filters (`.de-filter-section`) on the left and **SexLab current animations** (`.de-loaded-col`) on the right, then the filtered list full width below. The right column's list (`#de-loaded-list`, the bound thread's `thread.Animations` from SceneInfo `inThreadRegistries`; `A` = playing, `next` = pending pick) is absolutely positioned inside `.de-loaded-body`, so the filter column sets the row height and the list scrolls within it (at least five rows). The left column has the same tags / suppress / available tags / tag-type / `filter by gender` / `description` filter as Scene Creator (shared `SC` state, run against the scene's cast), a **name:** substring box (`#de-anim-name-filter`, 250 ms debounce → filter `_name_contains`, C++ `FilterSpec.name_contains`, case-insensitive on the row name, also narrows the tag counts), and the filtered list (`#de-anims-list`; `L` = loaded, `A` = playing). Queries use request id prefix `f` (`deRefreshFilterAnims` → `animDbQueryResult` → `deOnFilterAnimsResult`, `_n:125`, same `SC.filterChain` downgrade) and land in `DE.filterAnims` — never `SC.lastAnims`, which holds the editor's focus row. While the filter tab is up, `scRefreshAnims` (every shared filter control) re-queries this list instead.
- **Description Editor animation switch:** clicking a loaded row, or a filtered row (added to the loaded list first), makes it the editor's current animation at once as a **pending pick** (`DE.pendingSwitch {key, reg, row}`, `info.nextRegistry`); picking the playing row drops it. The pick is previewed (`deLoadPendingPreview`): its authored stages, and per live actor its AnimDB `O` / modifiers with `dressed = live && animation default` (stub rows fetch the full row via `r`). Header `Description: {name} (on unpause)`; stage nav and continue scene are disabled; Save writes the pick's AnimDB row without `_scene_sid`. The game applies it when it unpauses: **play** or a commit close sends `deSendPendingSwitch` → `{_scenes:[{_key,_mode:"active",_scene_sid,_active_registry,_reseed_defaults:1}]}` → `ApplyWebUICommit` → `Scene.WebUI_SwitchToRegistry(reg, reseed)` (set, or add with the 128-cap eviction; reseed → `CheckAnimationChange` → `ReloadAnimationDefaults`: the new animation's orgasm / speaking, dressing only toward undressed, change narration). The next push with that animation clears the pick (`deOnSceneAnimationPushed`) and the live values replace the preview. Cancel drops an unsent pick and restores a sent one. Papyrus runs while the overlay is paused, so the pick must be held in JS until unpause.
- Description Editor with a live scene: stage nav row (◀ previous / next ▶ send a stage-only `onSceneInfoCommit` → `ApplyWebUICommit` → `GoToStage`; `copy previous`; **play/pause** toggles the game pause (unpausing also sends a pending animation pick); header **Stop** (`#de-btn-stop`, right of **Save**, shown only for a live scene) opens the shared `#stop-dialog-overlay` **Stop scene** dialog (`stopDialogOpen(owner, onPick, explainOnly)`): forcefully / normally / gently / silently (`silent`) set SceneInfo `pendingStop` + `stopStyle` on the picked scene and close with commit → `ApplyWebUICommit` → `SceneStop_Target`; **custom** swaps to **Explain why** (textarea, Submit disabled while empty) → `stopStyle:'explain'` + `stopNarration` (Papyrus makes it `explain:<text>`); both Cancels only close the dialog; **continue scene** sends `onSceneNarrate {_scene_sid,_text}` → `WebUI_OnSceneNarrate` → `Scene.WebUI_OnNarrate` → `DirectNarration("The scene changes to <active-stage description>")`), tags and stage nav sit bottom-aligned in a side panel left of the actor table, and the actor table name buttons insert `{{sl.actors.N}}` into the active stage (no names row; hint line below the table). Every action button (nav, name, copy previous, continue) first **autosaves** dirty edits to disk without closing (`deAutoSave` → `deSaveToDisk`). **Save** writes the registry JSON and closes the overlay (`requestWebUIHide(true)`).
- Description Editor **style** pulldown (`#de-style-pulldown`, header left of **Save**): shown for the bound live scene (`deStyleSceneInfo`). A change sends `onSceneNarrate {_scene_sid,_style}` → `Scene.WebUI_OnNarrate` → `ChangeStyle` (style + animation speed + one `"<player|sender> changes from 'x' to 'y'"` DirectNarration; skipped while the orgasm window is open).
- Description Editor actor table **▲/▼** (`deMovePos`, live scene only) swaps actors in the SceneInfo's `positions` (and `SC.positions` if the Scene Menu shows the same info), and sets `dirty` + `pendingReorder`. `DE.posDraft` is not swapped because slot settings stay with the animation. A commit close (hotkey, Escape, Save) sends it via `flushSceneInfos`; Cancel drops it. `ApplyWebUICommit` calls `thread.ChangeActors` only if the order differs from `thread.Positions`.
- Description Editor **orgasm** button (`.orgasm_button`, first unlabeled column of `#de-actors-table`): shown only for a live scene (`deStopLiveInfo`). A press sends `onSceneNarrate {_scene_sid,_orgasm_pos}` (row index = `thread.Positions` index) → `Scene.WebUI_OnNarrate` → `WebUI_ForceOrgasm`: SexLab `thread.ForceOrgasm` (sends only `SexLabOrgasm`, never `HookOrgasmStart`). The `OrgasmIndividual` event path narrates when SeparateOrgasms is on, `no_orgasm` is 0 and the actor is not a DOM slave; otherwise `OrgasmCustom(actor, "", ignore_no_orgasm=true)` narrates.
- **Scene Menu** (`scene_creator_panel`): multi-select anim pool (`SC.selectedRegistries`). Each anim query result prunes the selection to listed rows and, if empty, auto-selects the top row. Click on an unselected row selects only it; Ctrl+click adds it; clicking a selected row removes it. **All** / **None** select every / no row. Adding a row (click or auto-select) reorders Positions to match its `_pos_genders` when every slot can be filled (exact gender, then same sex), then copies its `_clothed` / `_pos_no_orgasm` / `_pos_speaking_modifiers` into `dressed` / `O` / `modifiers` (even with override on); a reorder under the `positions` filter requeries. **Positions** always lists nearby SexLab-eligible actors (`selectable`, status `ok` or `sexlab`) as unselected grey rows even when they are not in the current scene; click name/`#` to add (SexLab cap 5) or remove. Ineligible nearby (`child`/`cmbt`/`ostim`/`dead`/`load`) stay off that table. They are not auto-joined. **override animation settings** toggle (`#sc-override-toggle`, above Positions; `SC.positionOverride` / SceneInfo `positionOverride` / commit `_position_override`, default off): off greys out `dressed` / `O` / `modifiers` (V, add/remove and ▲▼ reorder still work), and Papyrus ignores those values — Scene Creator skips its masks and locks, and the scene seeds each animation's defaults, including the first (`Scene.seed_first_animation`). Switching it off on a live scene runs `ReloadAnimationDefaults` once. On `new`: Start (apply + `pendingCreate` + commit-hide); the shared main-panel **Close** (no SceneInfo write) clears `show_scene_panel`. On active scene: Stop (`pendingStop`), A/N column, Update (writes anim pool into SceneInfo; SexLab in-thread cap 128 applied on commit), stage prev/next stay in the draft until Update/Stop. Layout: title row **Scene Creator** + style pulldown + Start (Stop when active), shared Close top-right; left column Positions (override toggle + **Save**, actor table, **range** pulldown); right column Filter. There is no activity field or scene-setting preset pulldown (intent still flows through `SC.intent` from TargetMenu / game state). **Save** (`#sc-btn-save-anim`, hidden on active scenes) writes the actor table's `dressed` / `O` / `modifiers` to the selected animation via `onAnimRegistrySave` with `_positions` only (`SaveAnimLocal` merges, stage descriptions kept) and updates the cached anim row; disabled unless override is on and exactly one animation is selected whose position count matches the actor count.
- **Filter-by downgrade:** each Scene Creator / Scene Menu open arms `gender → none` (`scArmFilterDowngrade`; default `gender`). A query returning zero anims steps to the next looser mode and re-queries, so the pulldown shows the mode actually used. Re-armed once actor meta resolves. **Do not query gender/positions mode while any position `_gender` is unknown** (`null`, not `0` — `0` is male). Nearby/player JSON includes `gender` from C++ `GetSex` for first paint; Papyrus `GetGender` overwrites via `actorAnimMetaResult` (creatures 2/3). Picking a mode manually pins it for that open (`positions` remains a pulldown option). Callers wanting a different start set `SC.filterByOnce` before `configureSceneCreator` (SceneStartPanel **Custom** uses `none` for nonsexual/affection methods, which leaves no fallbacks; other Custom uses `gender`). Shared Filter row (Scene Menu + Description Editor): `filter by gender:` + mode pulldown (`gender` / `none` / `positions`), then `description:` + `any` / `described` / `undescribed`; changing either pulldown re-queries anims and tags (`_has_description` when not `any`). `described` / `undescribed` use `_stage_has_description` or non-empty `_stage_descriptions`; JS also applies the same filter client-side on query results (including `_also_registries` merges). Gender filter downgrade does not run while a description filter other than `any` is active.
- **Description Editor** (`description_editor_panel`, the Scene view for a target in a scene): bound to the target's live scene (no scene pulldown). Shows the scene's current animation (or a pending pick, see **animation switch**); Description section header is **`Description: {anim name}`**; read-only anim tag chips show in the side panel. Names come from that scene's seeded `_positions` (`thread.Positions`, with `position_objs` name fallback). Live thread refresh: the overlay-Show `WebUI_SeedSceneInfos` carries the scene (no separate `WebUI_ConfigureFocusScene`); `WebUI_ConfigureIfOverlayVisible` on AnimationStart/StageStart and after a WebUI animation switch when the overlay is open; `seedSceneInfos` merges `_positions` / `_in_thread_registries` / `_active_registry` into existing scene keys. Opening the **animation filter** tab arms the filter downgrade (`scArmFilterDowngrade`). Per-stage table: editable **text** (`{{sl.actors.N}}`) + read-only **description** preview (`AnimationDB::SubstituteActors`). **Save** → `onAnimRegistrySave` → `AnimDb_SaveAnimLocal`. **Cancel** drops unsaved edits and closes the WebUI without committing (every live scene restores its Cancel snapshot). Layout: tags + stage nav in the left side panel beside the actor table (see above). **Actor table** (`#de-actors-table`, right under the header; columns `#`, `name`, `O`, `dressed`, `modifiers`): edits the focused animation's DB defaults (`_pos_no_orgasm`, `_pos_speaking_modifiers`, `_pos_clothed`), not the live scene's per-actor flags. `dressed` is a 👕/— toggle over the anidata `clothed` field (per-actor, authoritative over any clothing impression in descriptions — see `docs/developers/anidata-schema.md` §9), distinct from the live in-world strip/restore toggle used by Scene Creator/Target Menu's own `dressed` column. State is `DE.posDraft` / `DE.loadedPos` / `DE.posDirty`; **Cancel** restores it. **Save** adds `_positions: [{_no_orgasm, _speaking, _dressed}]` to the `onAnimRegistrySave` payload only when edited (`WebUI_OnAnimRegistrySave` → `orgasm_expected` + `speaking_modifiers` + `clothed`). Scene-pick anim rows are stubs (`_in_thread_anims` has no `_pos_*`), so JS fetches the row with `onAnimDbQuery {_type:"anim", _registry}` (request id prefix `r`, reply `_anims:[row]`).
- **Description Editor stage sync:** the SexLab thread owns the stage. ◀/▶ commit `{_scenes:[{_key,_mode:"active",_scene_sid,_stage_step:±1}]}` (Papyrus `ApplyWebUICommit` resolves `thread.stage + step`, clamped) and grey until the thread reports back; the editor never writes `info.stage` itself. `GoToStage` puts SexLab in state `Advancing`, which only finishes with game time running, so a step while paused auto-unpauses (`onGamePauseSet 0`) and re-pauses when the `StageStart` push (`_stage_started:1`) arrives (or after the 20 s pending timeout). The push from `ApplyWebUICommit` (no `_stage_started`) only moves the active row and keeps the nav greyed. `SkyrimNet_SexLab_Scene.StageStart` (click, GoToStage, or the game advancing on its own) first calls `WebUI_PushStage()` → `Animation_Menu_Configure({"_mode":"active","_scene_sid":N,"_stage":thread.stage,"_stage_only":1})`; `configureDescriptionEditor` handles `_stage_only` by moving the active row/nav only (no stage-text reload). Full pushes still carry `_stage`.
- **Scene view hotkey:** the hotkey opens TargetMenu, plus the Scene view when `show_scene_panel` is set (`WebUI_MaybeRestoreScenePanel` after hotkey / actor focus): Description Editor when the focus is in SexLab, else Scene Creator. While the player is animating, `ProcessHotkey` ignores the crosshair and focuses the first non-player in the player's `thread.Positions` (scanning from 0), or the player when solo (others via the actor pulldown).
- **Hotkey toggle:** if the overlay is visible, the menu hotkey hides it immediately (any ControlPanel focus actor) and does **not** dispatch `ProcessHotkey`. Hidden → `Menu.ProcessHotkey` → `Target_Menu_Open` (rebuild if same actor, else full open). Close does not clear `Target_Current`. Show/Focus only after DomReady; missing overlay HTML does not pause the game. Escape uses JS `handleGlobalEscape` when ready; C++ Unfocus/Hide if DomReady never fired.
- **Input swallow while open:** C++ `KeyHandler` is prepended to `BSInputDeviceManager` on register and on every Show. While the overlay is visible, `ProcessEvent` runs this plugin’s Escape/menu callbacks, then **unlinks** keyboard `kButton` and `kChar` events from the SKSE input list so SexLab and other SKSE/Papyrus `RegisterForKey` handlers do not fire (description editor typing). It always returns `kContinue` so mouse-move and mouse clicks still propagate (PrismaUI cursor + field focus). PrismaUI text fields receive typed characters via Win32. Overlay hidden → no unlinking; `kContinue` so the menu hotkey can open the UI.
- **Escape z-order:** one layer per keypress, highest first: open `.pulldown` menus → Save SceneSetting overwrite / name / confirm dialogs → IntentPanel (Cancel, no SceneInfo write) → YesNo silent No → Sex menu hide → TargetMenu cascade / Parameter panel (pop one nested pulldown, or close the Parameter/papyrus panel) → **close the WebUI with commit**, like the hotkey (`deAutoSave`, then `onWebUIHide {commit:true, endSession:true}`: `flushSceneInfos` applies changed state incl. a pending Description Editor pick, and the TargetMenu session ends). Escape never closes a main panel by itself (that is the main-panel **Close**) and never changes `show_scene_panel`. Scene Creator without TargetMenu (YesNo flow) still releases its Papyrus creator (`scReleaseOnEscape`). Root **Custom** closes an open Parameter/cascade panel before toggling Scene Creator.

## Scene HUD

Second PrismaUI view `PrismaUI/views/SkyrimNet_SexLab/hud.html` (`Hud.cpp`), created at `kDataLoaded`. Shown with `Show` only — never `Focus` (no pause, no cursor). Visible while the player is in an OrgasmEngine-managed scene, the overlay is hidden, and no pausing / dialogue / console menu is open (checked each 250 ms engine tick). Same position / zoom rule as `#left-column`. C++ pushes `hudUpdate({groups, focus, actors, keys, blocked, paused, speed, stage, stages})` only when it changes; `speed` is the speed level name (`OrgasmEngine::kSpeedLevelNames`: slow and gentle … fast and forceful), drawn between slower and faster. Each `actors[]` row is `{pos, name, enjoyment, flash, near, broken, magicka, stamina}`. `magicka` / `stamina` are whole-number % of max, and the mini-game group draws them as bars in front of the enjoyment bar. HUD keys live in `KeyHandler::SetHudKeys` (mouse buttons = DX 256+, `Config::HotkeyVkToDx` maps VK 1/2/4 and adds the 0x80 extended bit for arrows / End); while active, matched button events are unlinked so SexLab keys, favorites (1–4) and attacks never see them. calm / arouse / focus / slower / faster run in C++; end / previous / next dispatch `Menu.Hud_OnKey`. Engine, mini-game and API: [orgasm-engine.md](orgasm-engine.md).

## Lifecycle

- `kDataLoaded`: PrismaUI API, `CreateView("SkyrimNet_SexLab/index.html")`, JS listeners.
- `kPostLoadGame` / `kNewGame`: `WebUI_SetGameReady()` (enables input; reloads ActionCatalog from `webui/`; `configureControlPanel`).
- DomReady / game-ready: `configureControlPanel(BuildMainPanelsCatalog())` (includes `sceneSettings` from `scenes/*.json` for TargetMenu scene-start panels).
- Pulldown → JS `onMainPanelChange` → C++ `SwitchMainPanel` (close previous, open next). On a switch to (or re-select of) the Scene view, C++ resolves Description Editor vs Scene Creator and invokes `mainPanelDidOpen()` → bind the selected SceneInfo into that panel’s local draft (no Papyrus `WebUI_OnSceneConnectionChange`). Scene Menu **Update** writes into SceneInfo; SexLab anim-list apply happens on overlay commit. Full `SceneCreator_Open` / `Animation_Menu_Show` remain for YesNo / Custom / hotkey.
- Papyrus → C++ open; C++ → JS `showPanel` for `target_menu_panel` / `sex_menu_panel` / `scene_creator_panel` / `description_editor_panel` (both select the Scene view `scene_panel`; C++ picks the panel from the target; re-shows locally if that panel is already up).
- Catalog: `TargetMenu/Actor` or `TargetMenu/Scene` (from ControlPanel SexLabAnimatingFaction) + `actions_index.json` + `MainPanels/`; **Start** merges params and dispatches; action-panel **Custom** writes the panel draft plus scene setting into creator SceneInfo `new` and shows Scene Creator.

### TargetMenu UX

- Root `#target-panel` holds globals + root options + Cancel only (no `#target-name`). Each opened `pulldown` is its own sibling panel (nav stack); Parameters is a separate confirm panel with **Start** / **Custom**. The cascade row sits in the left column under ControlPanel; Scene Creator opens in the right main-panel host.

### Target sentinels

A mode may inject actor-pulldown entries that are not nearby FormIDs (`id` + `label`; optional `mainPanel`).

Selecting a sentinel:

- JS `onControlActorChange({ sentinel, formId: 0 })`
- C++ sets `Target_Current` to null and `FocusKind` to the sentinel id, then rebuilds the TargetMenu catalog
- `webui_focus_kind` eligibility decorator compares against `FocusKind` (`==` / `!=`)
- `ExecutePapyrusOption` allows a missing `target` Actor when the mapping source is `target` (Papyrus receives `None`)
- If the sentinel has `mainPanel`, C++ `SwitchMainPanel`s to that id; otherwise the current panel stays

`WebUI_GetFocusActor` / `WebUI_GetFocusKind` expose the pair to Papyrus. `Target_Menu_Refresh` is allowed when `Target_Current` is null if `FocusKind` is set. Clearing the TargetMenu session clears `FocusKind`.

Far-actor pin: a `data_table` row click still calls `ApplyControlActorFocus` with that FormID even if the actor is not nearby; SexLab already keeps the current focus actor in the nearby list. If the mode sets `rowClickMainPanel`, the overlay then opens that panel.

### Foreign main panels

`type: papyrus` MainPanels still only run zero-arg open/close and do not paint HTML. Use:

| type | Host | Payload (`WebUI_PushMainPanelData`) |
|------|------|-------------------------------------|
| `data_table` | `#data-table-panel` | `{ "panel": "data_table", "id", "columns", "rows", "truncated" }` |

Hard dependency ([Nexus](https://www.nexusmods.com/skyrimspecialedition/mods/148718)); the PrismaUI **plugin** is not shipped here.

**View path:** `CreateView("SkyrimNet_SexLab/index.html")` resolves under **`Data/PrismaUI/views/`**, not `SKSE/Plugins/`. This mod’s overlay HTML **is** shipped: `make release` copies `PrismaUI/` into FOMOD `core`. Missing file → open path looks fine; do not `Focus` until DomReady or the game pauses with a blank overlay (Escape is JS-only unless C++ Hide runs).

**Display scale:** Overlay matches SkyrimNet’s system — px design tokens (~15px base), `body.style.zoom` × Dashboard `ui_scale` × up-only 1080p baseline, scrollable left-column / panel shells. See [KNOWLEDGEBASE.md](../../KNOWLEDGEBASE.md).

After changing action `label`s: regenerate `actions_index.json` with `tools/generate_actions_index.py`.
